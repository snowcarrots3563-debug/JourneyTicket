## 1. 代码库与现状分析

### 1.1 技术结构

- UI 使用 Jetpack Compose，主题使用 Material 3；浅色/深色颜色方案已在 `ui/theme/Theme.kt` 中集中维护。
- 导航由 `ui/navigation/AppNavHost.kt` 统一管理，当前一级目的地为首页、旅途、设置；识图、确认、预览为流程页。
- 当前 `HomeScreen.kt` 是无状态 Composable，通过 `onGoCapture`、`onGoTimeline`、`onGoSettings` 接收导航回调。
- 当前首页使用 `LazyColumn`、安全区内边距、20dp 横向边距、20dp 圆角卡片和至少 44dp 的可触控高度。
- 当前首页已具备“旅程记录”标题、设置入口、“识别车票”主卡片和“我的旅途”卡片。
- 当前首页尚未具备：旅程统计摘要卡、“手动记录”入口、最近旅程列表以及首页专用的加载/离线/错误状态模型。
- 当前工程没有独立的 `HomeViewModel.kt`；后续若接入首页数据，应新增首页状态层，而不是把数据库读取直接写进 Composable。

### 1.2 Demo 可继承的页面结构

Demo A 方向明确了以下首页顺序：

1. 顶部标题与设置入口。
2. 深色旅程统计摘要卡。
3. 两个并列操作入口：识别车票、手动记录。
4. “最近旅程”分区及一张简洁旅程卡。
5. 首页/旅途/设置底部导航。

Demo 的核心不是装饰，而是让用户在首屏同时完成“立即识别”和“回看最近旅程”两类任务。实现时应保留信息优先级、留白、低饱和中性色和单一强调色，不引入渐变背景、复杂插画或模板化营销区块。

## 2. 背景与重构目标

### 2.1 背景

当前首页是功能入口集合，识别车票入口清晰，但用户无法在首页快速知道近期记录数量、最近一次行程或是否已有可回看的内容。Demo A 将首页定位为“快速识图 + 最近旅程”，需要把已有入口升级为一个可承载真实数据状态的首页。

### 2.2 重构目标

- 首屏明确提供一个主任务：点击“识别车票”开始图片识别。
- 同一屏提供回看任务：用户无需进入旅途页即可看到最近旅程摘要，并可继续查看详情。
- 使用统计摘要建立旅程记录反馈，但不得在数据不可用时伪造里程或次数。
- 让首页能够表达空数据、加载中、读取失败和离线缓存等真实状态。
- 通过统一 Material 3 主题、动态字体、安全区域和 TalkBack 语义，保证不同 Android 设备上的稳定体验。
- 保留纪念票的既有视觉与渲染结果：首页只负责入口和数据展示，不承担票面重绘。

### 2.3 成功指标

- 首页进入后，用户能在 3 秒内识别主操作和最近旅程入口。
- 在有数据、无数据、加载失败、离线四类状态下均有明确可执行的下一步。
- 统计摘要与最近旅程来自同一可信数据源；数据为空时不显示虚构数字。
- 所有主要交互的可点击区域不小于 48dp，并可被 TalkBack 识别为有意义的控件。

```text
首页

│  ├─ 页面标题：旅程记录
│  ├─ 副标题：把每一段车程，留成一页干净的记忆。
│  └─ 设置入口
├─ 旅程统计摘要
│  ├─ 统计标题：今年的移动轨迹
│  ├─ 旅程次数
│  └─ 里程（有可信数据时显示）
├─ 快速操作
│  ├─ 主操作：识别车票
│  └─ 次操作：手动记录
├─ 最近旅程
│  ├─ 最近记录卡片（最多展示首页约定数量）
│  ├─ 查看全部旅途
│  └─ 空状态/加载/错误/离线状态
└─ 底部导航
   ├─ 首页（当前）
   ├─ 旅途
   └─ 设置
```

### 3.1 首页与现有导航的关系

首页仍是一级目的地，底部导航仍保留“首页 / 旅途 / 设置”。“查看全部旅途”复用现有旅途目的地，不在本次文档中重构旅途页。设置入口复用现有设置目的地，不在本次文档中改造设置页。

“手动记录”在当前源码中尚无对应路由和业务入口，因此不能直接做成无效按钮。实现前必须确认是否已有隐藏的手动记录能力；若没有，应先定义路由和数据契约，或在本版本明确将该入口置为未启用状态并给出解释。

## 4. 用户核心任务与页面主路径

### 4.1 核心任务

| 优先级 | 任务 | 首页承接方式 | 完成标志 |
| --- | --- | --- | --- |
| P0 | 从车票图片生成旅程 | 点击“识别车票”进入现有识图流程 | 到达识图页并可选择图片 |
| P0 | 回看最近旅程 | 点击最近旅程卡片 | 到达既有票面/旅程详情 |
| P1 | 查看全部旅程 | 点击“查看全部旅途”或底部“旅途” | 到达既有旅途页 |
| P1 | 补录旅程 | 点击“手动记录” | 进入已确认的手动记录流程 |
| P2 | 调整应用设置 | 点击右上角“设置”或底部“设置” | 到达既有设置页 |

### 4.2 主路径

**路径 A：快速识图**  
首页 → 点击“识别车票” → 进入现有识图页 → 图片选择/拍照 → 现有确认与纪念票流程。

**路径 B：回看最近旅程**  
首页 → 点击最近旅程卡片 → 进入现有旅程详情或票面预览；首页不复制票面渲染逻辑。

**路径 C：无记录用户**  
首页 → 统计摘要显示空数据 → 最近旅程显示空状态 → 点击主操作开始第一次识图；空状态不得阻塞主操作。

**路径 D：读取失败或离线**  
首页 → 显示可理解的状态说明 → 若存在本地缓存，继续展示最后一次缓存并标记时间；若无缓存，提供“重试”和“识别车票”操作。

## 5. 页面模块第一阶段定义

### 5.1 顶部标题与设置入口

- 标题固定为“旅程记录”，延续 Demo A 的大字号、左对齐和大留白。
- 副标题保留现有语义：“把每一段车程，留成一页干净的记忆。”
- 设置入口位于右侧，使用图标 + “设置”文字，点击区域不小于 48dp。
- 顶部应使用安全区域内边距；禁止把内容压到状态栏下方。
- 页面滚动后，顶部不强制吸顶；如后续需要吸顶，必须单独验证与底部导航的层级关系。

### 5.2 旅程统计摘要卡

- 位于顶部信息区之后，使用 Demo A 的深色高对比卡片作为视觉锚点。
- 展示统计周期、旅程次数；里程仅在数据源提供可信累计值时展示。
- 卡片可点击时，整个卡片进入旅途统计/旅途页；若没有对应详情路由，则卡片仅作为摘要，不添加误导性的箭头。
- 统计数字使用等宽数字，避免数字变化造成布局抖动。
- 加载时使用固定尺寸骨架；错误时保留标题并显示“暂时无法读取统计”。

### 5.3 “识别车票”主操作

- 使用强调色或强调色容器，视觉权重高于“手动记录”。
- 文案为“识别车票”，辅助文案为“从图片提取行程”。
- 点击后立即进入现有识图流程；不得在本按钮后增加重复的图片来源弹窗逻辑，图片来源选择应由识图页按既有流程处理。
- 处理导航中的重复点击：点击后进入 loading/disabled 状态，直到导航事件消费完成。

### 5.4 “手动记录”次操作

- 使用与主操作同构但更弱的表面样式，保持并列关系。
- 文案为“手动记录”，辅助文案为“补充一段旅途”。
- 当前源码未发现对应路由；在产品确认前不得伪造完成路径。
- 若本版本暂不实现，应使用不可用状态或暂时隐藏，并在发布说明中明确，不得点击后无响应。

### 5.5 最近旅程列表

- 分区标题为“最近旅程”，位于快速操作之后。
- 首页只展示有限数量的摘要卡，避免替代旅途页；建议首版最多 3 条，具体数量由小屏可视高度验证决定。
- 每张卡显示日期、起点、终点、车次和关键时间；车站名不截断成无法识别的省略号，必要时允许两行。
- 卡片点击进入现有详情/票面预览路径；不得在列表卡片内重新生成票面。
- 有数据时提供“查看全部旅途”；无数据时显示引导首次识图的空状态。

### 5.6 底部导航

- 保留三个一级入口：首页、旅途、设置。
- 当前首页使用强调色指示，非当前项使用中性色；图标和文字均需存在，不依赖颜色单独表达状态。
- 遵守系统手势区和安全区域，导航栏内容不得被底部手势条遮挡。
- 底部导航只负责一级页面切换，不承载识图流程中的返回或确认操作。

### 5.7 页面状态

首版必须为以下状态预留明确布局，而不是只实现成功态：

| 状态 | 统计摘要 | 快速操作 | 最近旅程 |
| --- | --- | --- | --- |
| 加载中 | 固定尺寸骨架 | 可点击但避免重复触发 | 3 条骨架卡 |
| 有数据 | 显示真实统计 | 正常可用 | 展示最近记录 |
| 空状态 | 显示 0 或“暂无记录” | 识别车票可用 | 引导“从识别车票开始” |
| 读取失败 | 显示失败原因 | 识别车票可用 | “重试”与说明 |
| 离线 | 展示缓存并标记时间 | 识别入口按网络要求反馈 | 缓存列表可读，必要时显示离线标记 |

## 6. 已实施的首页基础版本

本阶段已将首页基础结构接入现有工程，作为后续视觉打磨和真机验收的起点：

- 新增 `ui/home/HomeViewModel.kt`，从 `TripRepository.observeTimeline()` 聚合最近记录。
- 首页统计改为按车票出发年份计算，不使用全量记录冒充年度统计。
- 首页展示最多 3 条最近旅程，使用现有 `TicketRecordEntity` 字段。
- 新增空状态、读取错误状态和固定尺寸加载占位。
- “识别车票”继续进入现有 `CAPTURE` 路由。
- 新增“手动记录”路由，复用确认页字段编辑和存档用例；手动模式不调用识图 API。
- 手动记录的始发站、终到站、车次号、开车时间未填写完整时，禁用生成和存档操作。
- 统计、首页列表和票面渲染保持数据与模块隔离；未改动 `render` 包。

该版本仍需进行模拟器视觉验收。最近旅程卡片当前复用既有旅途页导航，后续如需直接进入具体票面预览，应在导航层补充 recordId 传递，不在首页组件内读取渲染器。
